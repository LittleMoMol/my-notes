## 3-1 算法思维与复杂度分析

> [!question] 为什么两个能够得到相同结果的算法，计算效率可能相差很大？
> 
> 1. 即使两个算法都是 $O(n)$，但它们的常数因子不同，耗时就会差很多。
> 2. 顺序访问数组通常比链式结构、随机访问快得多，因为 CPU 缓存、预取机制利用率更高
> 3. 同样思路，用 C++ 手写循环和 python 等解释型语言高层抽象，开销差距可能达到几倍到几十倍

> [!question] 时间复杂度与程序实际运行时间有什么区别？
> 
> 总共需要计算 $100n^2 + 999n$ 次和需要计算 $n^2 + n$ 次的算法的复杂度都是 $O(n^2)$ 
> 
> 故时间复杂度关注输入规模去向无穷大时增长的趋势，并忽略常数因子与低阶项，用于理论比较、算法选择，并不反映具体某一次运行耗时
> 
> 而实际运行时间受数据规模较小时常数因子、硬件、编译器、操作系统、输入输出共同影响
> 
> *注意*：一些大常数复杂度低的算法，可能在小数据的情况下，表现的不如小常数复杂度高的算法

**适应性 (adaptivity)**：一个算法能够利用输入中已经存在的“好结构”（有序性）来减少计算。
- 冒泡排序是适应性，选择排序是非适应性的

**算法思维的核心**：避免不必要的计算！

当精确解的代价高到无法承受时，我们转向寻找“足够好”的近似解。

​**最坏情况分析**虽然在理论上很重要，因为它提供了一个性能的绝对下限，但它有时可能会过于悲观。

**平滑分析**：将微小的随机噪声引入到分析模型中，对于最坏情况的输入，我们给这个输入的每个数据点加上一点点高斯噪声，那么算法的期望运行时间可能就会大大减少。这样在理论上可能失败的算法，在实践中却能取得辉煌的成功。

*优化实例*：并查集的按秩合并与路径压缩、素数筛法的朴素筛到埃氏筛再到线性筛

**计算的物理现实** 
- 改变数据在内存中的存储方式​。计算机从主内存读取数据比从高速缓存（Cache）要慢得多，高速缓存一次会读取一个“缓存行”（比如 64 字节）的数据。如果我们能让相邻使用的数据，在内存地址上也同样邻近，那么当 CPU 读取一个数据时，它的邻居数据很可能已经在同一个缓存行里被顺便读进高速缓存了
- **莫顿编码** (Morton ordering)，一种神奇的“空间填充曲线”，就能做到这一点。它能将多维空间坐标映射到一维的编码，同时保持空间的局部性。通过按莫顿码的顺序存储粒子，我们大大提高了内存访问的局部性​。虽然邻居查询的渐进复杂度仍然是 $O(N)$，但实际运行时间可能会缩短数倍。

**NP-困难问题**：任何试图找到绝对最优解的精确算法，在最坏情况下都不得不面对着指数级的搜索空间。这就是所谓的 NP-困难问题，在计算理论中，它被认为是“最难的一类问题”。
- 理论计算机科学最深刻的谜题：P vs NP 问题。简单来说，就是“验证一个解的正确性”是否比“从零开始找到一个解”要容易？
- 对于一个布尔可满足性问题（SAT），给你一个变量赋值，你很容易就能验证它是否正确；但要你凭空找出一个满足所有条件的赋值，则可能需要尝试指数多次。

在现实世界中，算法运行在物理的硬件上。CPU、GPU、内存、网络……它们都有自己的“物理定律”。一个真正高效的算法，必须与硬件共舞，而不是逆其道而行。
- *例子*：在高性能计算（HPC）领域，当我们在多台计算机上并行求解一个偏微分方程（PDE）时。问题被分割成许多小块，每个处理器负责一块。计算量（“体积”）取决于小块的大小，而处理器之间需要交换边界信息，通信量（“表面积”）则取决于小块的周长。物理学告诉我们，同样体积的物体，球形的表面积最小。同样地，为了最小化通信开销，我们应该将问题划分成尽可能“方正”的子域，使得每个子域的“表面积/体积比”最小。这个简单的几何直觉，可以被严格地数学推导出来，它揭示了并行算法设计中计算与通信之间最核心的权衡。

在现代大规模并行计算中，“通信”往往是比“计算”更宝贵的资源。数据在处理器之间、在内存与 CPU 之间移动，可能比执行浮点运算本身要慢上几个数量级。于是，催生了一类“**通信避免**”算法。
- *例子*：在处理一个“瘦高”型矩阵（行数远大于列数）的 QR 分解时，经典算法需要频繁地在所有处理器间进行全局通信。而“通信避免”的 TSQR 算法则反其道而行：它让每个处理器先在本地进行更多的计算，将自己的数据块“压缩”成一个小得多的 R 矩阵，然后再将这些小矩阵在处理器间传递和合并。

这种与硬件共舞的思想，在图形处理器（GPU）编程中体现得淋漓尽致。GPU 拥有数千个微小的计算核心，像一支庞大的军队。要发挥其威力，关键在于“协同作战”。算法设计者必须考虑如何将数据高效地加载到 GPU 的高速“共享内存”中，以减少对慢速全局内存的访问；如何组织线程（计算士兵）成“线程束”（warp），确保它们步调一致地执行相同指令，避免“分歧”（divergence）导致的效率损失；以及如何分配资源（如寄存器、共享内存），以达到最高的“占用率”（occupancy），让尽可能多的计算单元保持忙碌。

## 3-2 计算机数值表示

### 3-2-0 思考

> [!question] 为什么计算机通常不能精确表示 `0.1`？
> 
> 根本原因在于进制转换和有限的存储空间
> 
> 我们在日常生活中使用十进制，而计算机内部使用二进制。在十进制中，像 `1/3 = 0.33333...`这样的分数是无限循环小数，无法被精确表示。同理，在二进制中，`0.1`这个看似简单的十进制分数，换算成二进制是一个无限循环小数。
> 
> 计算机的存储单元是有限的，它只能截取这个无限循环二进制数的前面一部分，然后进行舍入。因此，计算机里存储的并不是真正的 `0.1`，而是一个非常接近 `0.1` 的近似值。
> 
> **结论**：就像我们无法用有限的小数位数写出 `1/3`一样，计算机也无法用有限的二进制位数写出 `0.1`。这是由底层数制决定的先天不足。

> [!question] 为什么浮点数运算不一定满足数学中的结合律？
> 
> 结合律是指 `(a + b) + c = a + (b + c)`。浮点数不满足结合律，正是由于上面提到的精度损失和舍入误差导致的。
> 
> 核心原因：大数“吃掉”小数。当两个数量级相差很大的浮点数进行加减运算时，为了对齐小数点，较小的数会被右移，其低位有效数字可能会超出存储范围而被丢弃。这就导致了“大数吃小数”的现象。
> 
> 例子：`a = 1.00, b = 0.004, c = 0.004` 
> 
> `(a+b)+c = (1.00+0.004)+0.004 = 1.00+0.004 = 1.004 = 1.00` 
> `a+(b+c) = 1.00+(0.004+0.004) = 1.00+0.008 = 1.008 = 1.01` 

### 3-2-1 IEEE 754 标准
**科学计数法**，如 $3.0\times 10^8$，它​将数字的**精度**​（由有效数字的位数决定）和**范围**​（由指数决定）分离开来。
- 它牺牲了绝对的均匀精度，换取了极其宽广的表示范围。

在计算机的浮点数系统中，任何一个数字都可以被表示为：`值 = 符号 × 尾数(Significand) × 2^{指数(Exponent)}`，这里的

浮点数表示法，其核心是著名的 IEEE 754 标准，以最常见的 IEEE 754 双精度 （binary64）格式为例，看看一个数字是如何被编码到 64 个比特位中的。这 64 个比特位被分成了三个部分：
- **符号位** (Sign Bit)：1 位，最简单的一部分，0 代表正数，1 代表负数。
- **指数位** (Exponent)：11 位，它并不直接存储指数值 $E$，而是存储一个加上了偏置量 (bias) 的值。对于双精度，偏置量是 1023。也就是说，实际的指数 $E = 存储值 - 1023$。这种设计使得指数的正负比较可以像比较无符号整数一样简单高效。
	- 对于 $k$ 位指数，其偏移量为 $2^{k-1}-1$ 
- **尾数部分** (Fraction)：52 位，对于大多数数字（我们称之为**规范数** (Normalized Numbers)），标准规定尾数的整数部分永远是 1，因此这个 1 不需要被存储，是“隐藏”的。我们只需要存储小数点后面的 52 位小数部分。这样，我们用 52 位的存储空间，获得了 53 位的精度。

**ULP**：这种表示系统会导致数字不是均匀分布的！在同一个指数区间，比如 $[2^k, 2^{k+1})$ 内，所有数字共享相同的指数 $k$ 。它们之间的区别仅在于 $52$ 位的尾数部分。尾数部分可以看作一个从 0 到 $2^{52}-1$ 的整数。每当这个整数加 $1$ ，就代表了数轴上的下一个可表示的数字。 这个最小的步长，也就是两个相邻浮点数之间的距离，被称为 **ULP** (Unit in the Last Place)。
- 在一个指数为 $k$ 的区间内，这个距离是多少呢？改变尾数的最低有效位，其值的变化是 $2^{-52}$。再乘上该区间的尺度 $2^k$，我们得到：$\text{ULP}(k) = 2^{-52} \times 2^k = 2^{k-52}$，这个简单的公式揭示了一个深刻的规律：
	- 在区间 $[1, 2)$ (即 $k=0$ )，数字之间的间距是 $2^{-52}$ 
	- 在区间 $[2, 4)$ (即 $k=1$ )，间距变为 $2^{-51}$，是前一个区间的两倍
	- 在区间 $[1024, 2048)$ (即 k=10 )，间距是 $2^{10-52} = 2^{-42}$ 
- 绝对间距随着数字的增大而增大。这意味着，你可以在 $1.0$ 附近表示极为精细的差异，但在一百万附近，最小的步长已经变得相当可观了。

**相对精度**、**机器埃普西隆**​：计算一下间距与数字本身大小的比值：$\frac{\text{ULP}(k)}{x} \approx \frac{2^{k-52}}{2^k} = 2^{-52}$ 为常数，称为**相对精度**。这个值，即在 1.0 附近的 ULP，被称为**机器埃普西隆** (Machine Epsilon, $\epsilon$)。它代表了 1.0 和下一个更大的可表示数之间的差值。
- 对于双精度，$\epsilon = 2^{-52}$ 

**单位舍入误差** (Unit Roundoff, $u$)：在“四舍五入到最近”的模式下，任何实数被舍入时，其产生的最大相对误差是 $\epsilon$ 的一半，即单位舍入误差 $u = \epsilon/2 = 2^{-53}$ 
- 这个近似恒定的相对精度是浮点数系统设计的基石。它意味着，无论你是在测量星系间的距离还是原子的大小，你的测量工具（浮点数）都有着大致相同的“相对”灵敏度。

通过以上分析可以知道：
1. 大于 $2^{53}$ 的一些整数不能被表示出来
2. 一个有理数只有在它的分母（化为最简形式后）的质因数只有 $2$ 的时候，才能被有限的二进制小数表示。

### 3-2-2 次规范数、无穷大与NaN

当一个数字小到一定程度，它的指数达到了最小值，再除以 2 会发生什么？一种简单粗暴的方法是直接把它变成零，这被称为**突变到零** (Flush to Zero, FTZ)。

**次规范数**：IEEE 754 提供了一个更优雅的方案：​**平滑下溢** (Gradual Underflow)。当指数无法再减小时，系统会放弃尾数中隐藏的那个“ 1 ”，允许它变为“ 0 ”。这些数字被称为**次规范数** (Subnormal Numbers)。
- 次规范数的表示形式是：$\text{值} = \text{符号} \times (0.\text{f})_2 \times 2^{-1022}$，指数被固定在最小的规范指数上，而尾数的小数部分可以开始包含前导零。
- 每当一个次规范数再除以 2 ，就相当于它的尾数右移一位，精度逐渐丧失，但数值平滑地、一步一步地走向零。

**无穷大** (Infinity)：当指数位全为 1 且尾数部分全为 0 时，就表示无穷大（根据符号位区分正负）。
- 它处理像 1.0 / 0.0 这样的操作，使得计算可以继续下去，而不是崩溃。

**NaN** (Not a Number)：当指数位全为 1 且尾数部分不全为 0 时，表示“不是一个数”。
- 它用于表示无效操作的结果，比如 `0.0 / 0.0` 或 `sqrt(-1)` 
- 任何涉及 NaN 的比较（甚至 `NaN == NaN`）都返回 `false`。这使得我们可以通过 `x != x` 来检测一个值是否是 `NaN` 
- `NaN` 还分为两种：
	- **静默 NaN** (Quiet NaN, **qNaN**)：它在计算中“安静地”传播。任何运算只要有一个操作数是 qNaN，结果就是 qNaN 
	- **信令 NaN** (Signaling NaN, **sNaN**)：它是一种“警报”。当 sNaN 参与运算时，它不仅会像 qNaN 一样传播，还会触发一个“无效操作”的异常信号。这可以被用来捕获未初始化的数据或其他潜在的严重错误。 

上面的特殊值让整个系统在面对除以零或无意义的计算时，能够以一种可预测和可控的方式行事。

### 3-2-3 舍入误差
​舍入 (Rounding) 不可避免，IEEE 754 定义了多种舍入模式，比如“朝零舍入”、“朝向正无穷/负无穷舍入”，以及最常见的​“舍入到最近，**偶数优先** (Round to Nearest, ties to Even)”。这个“偶数优先”规则是为了在统计上避免偏差，当一个数恰好在两个可表示数的正中间时，它会选择那个尾数最低位为偶数的。

然而，即使有最公平的舍入规则，每一次舍入都可能引入一个微小的误差，其最大值不超过半个 ULP。单个误差虽小，但在大规模计算中，每一步的舍入误差会不断累积，可能会彻底淹没真实的结果。

> [!danger] 双重舍入 (Double Rounding) 的危机
> 
> 一些旧的处理器架构为了提高精度，其内部使用一种更高精度的 80 位格式（比如 64 位尾数）进行计算，然后在存储结果时再将该结果舍入到标准的 64 位双精度格式（ 53 位尾数）。看似更精确，但这会导致一个可复现性的危机！
> 
> 考虑一个精心构造的数字，它恰好比两个 53 位精度可表示数的中间点高一点点。
> 
> 直接舍入​：当它直接舍入到 53 位精度时，它会“向上”舍入到较大的那个数。
> 
> 双重舍入​：当它先舍入到 64 位精度时，由于 64 位精度更高，这个微小的偏移可能不足以让它跨越舍入边界，于是它被舍入到了那个恰好在两个 53 位精度数中间的值。然后，当这个中间值再被舍入到 53 位精度时，“偶数优先”规则生效，它可能会被“向下”舍入到较小的那个数。
> 
> 最终，同一个计算在不同架构的机器上得到了两个不同的结果！
> 
> 这个双重舍入问题是科学计算中“**可复现性危机**”的一个重要来源。

## 3-3 浮点运算

### 3-3-1 理论

浮点算术提供的是恒定的​相对误差，而不是恒定的绝对误差。一个数的误差大小，与这个数自身的量级成正比。

**第一条铁律**：永远不要用 `==` 来比较两个浮点数是否相等。
- **舍入误差**导致的

**第二条铁律**：在对一系列数值差异巨大的数求和时，从最小的数加起，可以得到更精确的结果。
- *例子*：对谐波级数 $\sum_{n=1}^N \frac{1}{n}$ 的求和问题中，顺序求和误差较大，逆序求和误差较小
- **非结合律**导致的

**灾难性抵消**：发生在两个非常相近的数相减时。假设两个数，它们的前 10 位有效数字都完全相同，只在第 11 位之后有差别。当它们相减时，前 10 位有效数字互相抵消，结果的有效数字只剩下了后面那些原本不那么可靠的“噪声”位。

*重现很困难*：完全相同的源代码，在两台都声称符合IEEE 754标准的计算机上运行，得出的结果却无法逐比特地重现。为什么？因为即使标准统一，执行的细节却可能不同： 
- **融合乘加** (**FMA**)：一些现代 CPU 可以将 $a \times b + c$ 合并为一条指令，只进行一次舍入。而老式 CPU 则需要两步（一次乘法舍入，一次加法舍入）。一次舍入和两次舍入，结果自然不同。 
- **编译器优化**：为了追求极致速度，编译器（例如使用 `-ffast-math` 选项）可能会对你的代码进行代数重排，比如把 `(a+b)+c` 变成 `a+(b+c)`。我们已经知道，这在浮点世界里是“非法”操作，会改变结果。
- **并行计算**​：在并行求和时，不同线程计算的局部和的最终合并顺序，在不同架构或运行环境中可能是不同的。不同的加法顺序，导致不同的结果。
- **硬件差异**​：一些古老的 CPU（如 x87 协处理器）在内部使用 80 位的扩展精度进行计算，只在存回内存时才舍入到 64 位。而现代 CPU（如 SSE/AVX）则全程使用 64 位。不同的中间精度，导致不同的舍入累积。

总结：舍入误差、非结合律、灾难性抵消

### 3-3-2 应用

一个好的数值模拟，不仅在于减小每一步的误差，更在于控制误差的性质​，使其不破坏系统所遵循的基本物理定律。

**混合精度策略**：将计算密集但对精度不那么敏感的部分用低精度快速完成，而将决定算法稳定性和最终精度的关键部分用高精度（如64位双精度）来“精雕细琢”。

## 3-4 数值误差分析

### 3-4-0 思考

> [!question] 什么是舍入误差和截断误差？
> 
> **舍入误差**（Round-off Error）：是指由于计算机只能用有限位数的二进制表示实数，在计算过程中对无限小数进行“四舍五入”或截断所带来的微小误差。它源于数字表示的精度限制（如 float、double 的位数限制），即使在数学上精确的公式，在计算机中执行也会累积这类误差。
> 
> **截断误差**（Truncation Error）：是指用数学上的近似方法代替精确方法所产生的误差。例如用泰勒级数的前几项代替整个无穷级数，或用数值积分公式代替精确积分。它源于算法本身的近似性质，与计算机无关，即使在理论上也存在。

> [!question] 什么是前向误差和后向误差？两者分别回答什么问题？
> 
> **前向误差**（Forward Error）是指数值计算结果 $\tilde{x}$ 与真实精确解 $x$ 之间的绝对或相对差异，即 $\frac{|\tilde{x} - x|}{|x|}$。它回答的问题是：“我的计算结果错得有多离谱？”（关注结果本身的偏差）。
> 
> **后向误差**（Backward Error）是指为了使计算结果 $\tilde{x}$ 成为某个问题的精确解，需要将原问题的输入数据 $d$ 改变多少，即找到最小的扰动 $\Delta d$ 使得 $f(d+\Delta d) = \tilde{x}$。它回答的问题是：“我的计算结果对应哪个稍微改动过的输入问题的精确解？”（关注输入扰动的稳定性）。
> 
> 后向误差常用于分析算法的数值稳定性——若后向误差很小，说明算法本身稳定，误差主要由不可避免的舍入引起。

### 3-4-1 截断误差与舍入误差

**截断** (chopping)：在计算机有限的内存空间里，一切都必须被“量化”。想象一个只能记录小数点后三位的简陋计算机，当我们想存储 $\frac{2}{3} = 0.666666...$ 时，它别无选择，只能“斩首”掉多余的位数，得到一个近似值 $p^* = 0.666$。这个过程被称为**截断**。
- 绝对误差 $|p - p^*|$ 
- 相对误差 $\frac{|p - p^*|}{|p|}$ 

**混合容差** (mixed tolerance)：在函数的零点附近，绝对误差比相对误差更有意义。因此，在现代科学计算软件中，人们普遍采用一种**混合容差**，即 `error = max(atol, rtol * |true_value|)`。它在远离零点时表现为相对误差，在靠近零点时自动切换为绝对误差。

**截断误差** (Truncation Error)：它源于我们用有限的过程去近似一个无限的过程。微积分中的导数和积分，本质上是极限过程；许多函数可以用无穷级数来表示。在计算时，我们不可能处理无限。我们用有限差分代替导数，用有限项的和来代替无穷级数。这种“截断”带来的误差，就是截断误差。
- 只要我们的近似模型没有完美捕捉到数学对象的全部信息，截断误差就存在。 

**舍入误差** (Round-off Error)：它源于计算机无法精确表示所有实数。每一次加、减、乘、除，结果都可能需要被“四舍五入”到最接近的可表示的浮点数。
- 这个微小的误差，在单次运算中看似无害，但它会像滚雪球一样在成千上万次计算中累积，有时甚至会以灾难性的方式爆发。

*截断误差与舍入误差的关系*：通常，为了减小截断误差，我们需要把计算过程做得更精细，这就意味着执行更多的运算。更多的运算，就意味着累积更多的舍入误差。
- 所以寻找最佳步长很重要！

### 3-4-2 病态问题

​**条件数** (Condition Number)、**病态的** (ill-conditioned)：一个问题的**条件数**衡量了其输出相对误差与输入相对误差的比值。如果一个问题的条件数很大，我们称之为**病态的**。这意味着，即使输入的数值只有一丝丝的扰动（比如由测量或舍入引起），输出结果也可能发生翻天覆地的变化——无论我们使用多么精妙稳定的算法。

### 3-4-3 向后误差分析

​**前向误差** (forward error)：我的计算结果与真实答案相差多少？

​**后向误差** (backward error analysis)：我的计算结果，是否是另一个‘略有不同’的输入问题的‘精确’解？

**后向稳定的** (backward stable)：以计算几何平均数 $g=\sqrt{xy}$ 为例。经过浮点运算，我们得到的结果 $\hat{g}$。后向误差分析表明，虽然 $\hat{g}$ 可能不完全等于 $\sqrt{xy}$，但它却精确地等于某个被微小扰动过的输入的几何平均数 $\sqrt{\hat{x}\hat{y}}$。如果我们可以证明，这个“被扰动过的问题”（由 $\hat{x}, \hat{y}$ 定义）与我们“原始的问题”（由 $x, y$ 定义）非常接近，那么我们就说这个算法是**后向稳定的**。
- 即使无法得到绝对精确的答案，只要我们的算法能确保我们得到的是一个“邻近”问题的精确解，那么这个算法就是可靠和值得信赖的。
- 后向误差分析将误差的焦点从不可捉摸的“真解”转移到了我们能够掌控和分析的算法本身的行为上。

**验证** (Verification) ​与**确认** (Validation) 
- **验证**：“我们是否正确地求解了方程？”，它在确保我们的代码和算法在有限精度的数字世界里行为端正。
- **确认**：“我们求解的方程是否正确？”，它需要将计算结果与真实世界的实验数据进行比对。
- 只有同时做好了这两件事，我们才能充满信心地宣称，我们通过计算，真正地洞悉了自然。

### 3-4-4 应用

​**Kahan 求和算法**：这个算法像一个细心的会计，它在每一步加法之后，都会计算出因为舍入而“丢失”的那一部分，并在下一步的计算中把它补偿回来。
- 通过这种方式，Kahan 求和算法能够以远高于朴素求和的精度，追踪一个长序列的和。

**融合乘加** (Fused Multiply-Add, **FMA**)：现代处理器中普遍存在一个叫做**融合乘加**的指令。这条指令可以在一个步骤内完成 $ax+b$ 的计算，并且只在最后进行一次舍入。
- *应用*：当用来计算判别式时，它可以计算 $b \times b + (-4a \times c)$。通过将两次乘法和一次减法“融合”起来，它避免了在计算 $b^2$ 和 $4ac$ 时的中间舍入步骤。
- FMA 的存在，是软件算法与硬件设计协同对抗数值误差的绝佳范例。

**离散化**：我们的世界是连续的、模拟的。而控制这个世界的计算机，是离散的、数字的。将描述连续系统行为的微分方程，转化为计算机可以执行的离散步骤。这个转化的过程，就叫做​**离散化**。

物理学的灵魂在于守恒律——能量守恒、质量守恒、动量守恒。一个好的数值模拟，应该尽可能地尊重这些神圣的定律。然而，不同类型的数值误差会对守恒律造成不同风格的破坏。

**重整化** (renormalization)：在长时间的模拟中，我们常常需要周期性地对系统进行**重整化**——比如，手动将概率和或总质量调整回其应有的值——以此来对抗这种由舍入误差引起的影响。

## 3-5 向前与向后误差分析

### 3-5-1 两种看待错误的方式：前向与后向视角

**向前误差** (forward error)：我们想计算一个真值为 $y$ 的量，但我们的程序给出了结果 $\hat{y}$，那么前向误差就是 $|\hat{y} - y|$ 

**后向误差** (backward error)：它将误差的来源从输出端追溯回输入端。它问的是：“我的算法所解决的，是哪个与原始问题略有差异的‘邻近问题’？”
- 如果这个“邻近问题”与原始问题的后向误差非常小，我们就称这个算法是**后向稳定的** (backward stable)。这就像说，虽然有风，但你的射击技术本身是可靠的，你只是精准地击中了一个被风吹偏的目标。

- **结构化后向误差** (structured backward error)：在许多物理问题中，描述系统的矩阵或方程具有特定的结构​。当我们进行后向误差分析时，我们不能满足于任意的“邻近问题”，我们希望这个邻近问题同样尊重这种物理结构。这就引出了​**结构化后向误差**的概念。
	- *例子*：在求解一个对称矩阵的特征值问题时，我们寻找的是“最近的那个同样对称的矩阵”，使得我们的计算结果是它的精确特征值对。这确保了我们的误差分析始终在有物理意义的框架内进行。

*例子* 

假设我们想计算 $f(a, b) = a - b$，其中 $a = 1.0000000000000001,\ b = 1.0$。真实答案 $y$ 是 $10^{-16}$。然而，计算机使用有限的浮点精度来存储和操作数字。当它计算 $\hat{y} = \mathrm{fl}(\mathrm{fl}(a) - \mathrm{fl}(b))$ 时（这里 $\mathrm{fl}(\cdot)$ 代表四舍五入到最接近的可表示浮点数），由于精度的限制，它可能会丢失 $a$ 中最末尾的关键信息，最终得到的计算结果 $\hat{y}$ 可能是 $0$ ，或者是一个与真值 $10^{-16}$ 相去甚远的数字。 

从前向误差的角度看，效果很差！相对前向误差 $\frac{|\hat{y} - y|}{|y|}$ 可能会非常大（如果 $\hat{y}=0$，误差甚至是 $100\%$），我们的答案毫无价值。

从后向误差的角度看，我们问：计算机计算出的结果 $\hat{y}$ 是哪个邻近问题 $(a+\delta a) - (b+\delta b)$ 的精确解？对浮点减法进行严谨分析可以证明，这个计算过程是后向稳定的。这意味着，我们总能找到极小的扰动 $\delta a$ 和 $\delta b$（其相对大小通常不超过机器精度，比如 $10^{-16}$），使得 $(a+\delta a) - (b+\delta b)$ 精确地等于我们计算出的 $\hat{y}$。所以我们的算法完成了一项略有不同的任务，它的后向误差是微不足道的。

这里就出现了一个悖论：一个“好”的（后向稳定）算法，为何会产生一个“坏”的（巨大前向误差）结果？

### 3-5-2 条件数

有些问题天生就是“敏感”的，对于一些问题，可能很小的输入误差都会导致巨大的输出误差；而另一些问题则非常“稳健”，微小的扰动几乎不会影响其整体稳定性。

**条件数** (condition number)：问题的这种内在敏感度，被一个称为**条件数**的量所刻画，通常记为 $\kappa$。条件数衡量了输出的相对变化与输入的相对变化之间的比率。
- *条件数的本质定义思想*：输出相对误差 ≈ 条件数 × 输入相对误差
- **病态的** (ill-conditioned)：一个巨大的条件数意味着问题是**病态的**，即对输入的微小扰动极其敏感。

$$
\text{相对前向误差} \approx \text{条件数} \times \text{相对后向误差}
$$

上式将​算法的质量​（由后向误差衡量）与问题的敏感性​（由条件数衡量）清晰地分离开来。一个后向稳定的算法是我们能期望的最好结果。如果问题本身是病态的，那么即使是最好的算法，也难以保证得到一个相对精确的答案。这并非算法的失败，而是问题内在的缺陷。

### 3-5-3 计算与现实

**后向误差分析**回答：“我是否正确地求解了我的方程？”，这是一个面向计算科学家的问题。
**模型验证**回答：“我是否写下了正确的方程？” 这是一个面向物理学家、工程师或领域专家的问题。

### 3-5-4 应用

在主成分分析（PCA）中，对于一个对称的协方差矩阵，其​特征值（表示每个主成分解释的方差量）总是良态的。这意味着数据中的微小噪声只会对解释的方差量产生微小影响。然而，其​特征向量（定义了主成分的方向）可能是病态的，特别是当两个特征值非常接近时。

## 3-6 条件、条件数与适定性

### 3-6-0 思考

> [!question] 什么是问题的病态性？
> 
> **问题的病态性**（Ill-conditioning）指的是：输入数据的微小扰动会导致输出结果发生巨大变化的数学问题特性。这类问题本身对误差（舍入误差、测量误差）非常敏感，本质上难以精确求解，与具体使用的算法无关。
> 
> 衡量指标通常是**条件数**（Condition number）：条件数大 → 病态；条件数接近 1 → 良态。
> 

> [!question] 问题的条件性与算法的稳定性有什么区别？
> 
> **问题的条件性**​
> 
> - 属于问题本身的性质，与算法无关。
> - 描述：输入误差被问题“放大”的程度。
> - 病态问题即使使用“完美”的算法，结果也可能很不精确。
>   
> **算法的稳定性**​
> 
> - 属于数值算法本身的属性，与具体实现有关。
> - 描述：算法在计算过程中是否会过度放大舍入误差或初始误差。
> - 稳定算法：误差增长可控；不稳定算法：自身会人为放大误差。
>   
> 简单关系：
> - 病态问题 + 稳定算法​ → 结果仍可能不精确（问题本身决定的局限）。
> - 良态问题 + 不稳定算法​ → 本来可精确求解，却被算法算坏了。

### 3-6-1 区分问题的病态与算法的不稳定

**问题的病态性**：一个对输入扰动极其敏感的问题，我们称之为**病态的** (ill-conditioned)

​**算法的不稳定性** (instability)：由于算法设计不当而导致误差累积的特性，我们称为​**算法的不稳定性**。

我们必须区分问题的内在困难（条件）​和​算法的执行好坏（稳定性）！
- 一个稳定的算法可以在一定程度上克服病态问题带来的挑战，但它无法改变问题本身的敏感天性。
- 而一个不稳定的算法，即使面对一个性质良好（​良态的，well-conditioned​）的问题，也可能把事情搞砸。

### 3-6-2 条件数的理论推导

**下面讨论可微函数的条件数** 

对于一个可微函数 $f(x)$，根据泰勒展开，当扰动 $\Delta x$ 很小时，输出的变化 $\Delta y = f(x+\Delta x) - f(x) \approx f'(x)\Delta x$。这就是说，输出的绝对变化大约是输入绝对变化的 $|f'(x)|$ 倍。因此，$|f'(x)|$ 就是问题的**绝对条件数**​。 

但我们通常更关心相对误差​。相对条件数 $K_{rel}(x)$ 衡量的是相对误差的放大效应。通过简单的推导，我们可以得到：$K_{rel}(x) = \left| \frac{x f'(x)}{f(x)} \right|$ 
- 这个公式告诉我们，问题的敏感性不仅取决于导数 $f'(x)$ （函数变化的快慢），还取决于输入 $x$ 和输出 $f(x)$ 本身的大小。

### 3-6-3 适定性

当条件数变得无限大时，我们就跨过了一条界线，从“病态”进入了“不适定”的领域。

法国数学家 Jacques Hadamard 提出一个**适定的** (well-posed) 问题必须满足三个条件：
- **存在性** (Existence)：解必须存在。
- **唯一性** (Uniqueness)：解必须是唯一的。
- **稳定性** (Stability)：解必须连续地依赖于输入数据（即，输入的小扰动只引起输出的小扰动）。 

一个病态问题仍然是适定的——它满足所有三个条件，只是稳定性很差（条件数很大）。而一个**不适定的** (ill-posed) 问题则至少违反了其中一条。

- *例子* 
	
	假设我们要寻找函数 $f(x)$ 的最小值。在最小值点 $x^\star$ 附近，函数的形状由其二阶导数矩阵 (​Hessian 矩阵 $H$) 决定。 
	
	如果 $H$ 的条件数 $\kappa(H)$ 很大，意味着函数的“等高线”是一些被极度拉长的椭圆。这就像在一个狭长、平缓的山谷里找最低点，稍微偏离一点方向，你可能会滑出很远。这个问题是病态的​，数值算法很难精确地定位谷底。
	
	如果 $H$ 是奇异的（即它有一个特征值为零），这意味着山谷在某个方向上是完全平坦的。那么，最低点就不是一个点，而是一整条线。解不唯一，违反了 Hadamard 的第二条准则。这个问题是不适定的​。

### 3-6-4 两种好方法！

1. **预处理** (Preconditioning)：对于那些虽然病态但仍然适定的问题，我们可以采用**预处理**。预处理并不改变问题本身，也不改变它的精确解。 我们解决的是一个与原问题等价但条件更好的新问题。它没有修复问题本身，但极大地改善了我们求解它的能力。
2. **正则化** (Regularization)：通过在原始问题中加入一个惩罚项，我们将一个不适定的问题，主动地、有控制地修改为一个邻近的、适定的新问题。这个新问题的解，我们称之为**正则化解**。它不是“真”解，它带有一点**偏倚** (bias)，但它换来了**稳定性** (stability)——它不会因为数据中的微小噪声而剧烈波动。在实践中，这种用一点点偏倚换取巨大稳定性改善的交易，是非常划算的。

## 3-7 数值算法的稳定性

根对系数的敏感度，取决于该根处多项式导数的值。如果导数值很小（意味着函数曲线在根附近很平坦），那么根就会对系数的扰动异常敏感。对于高阶多项式，这种敏感性可能被放大到令人难以置信的程度。

**威尔金森多项式**：考虑一个 20 次多项式，它的根恰好是整数 $1, 2, 3, \ldots, 20$。这是一个定义清晰、根也十分“规矩”的多项式。1963年，伟大的数值分析学家 James H. Wilkinson 发现，如果仅仅对这个多项式的某一个系数（比如 $x^{19}$ 的系数）做一个极其微小的扰动（大约 $10^{-10}$ 的量级），多项式的根会发生惊人的变化。一些根几乎没动，但另一些根，比如 10 和 11 附近的根，不仅移动了巨大的距离，甚至变成了带有很大虚部的复数！

Wilkinson 多项式的例子是一个深刻的警示：即使一个问题看起来很“好”（比如根是良好分离的整数），它也可能隐藏着极端的病态。

## 3-X 习题
### 3-4 习题 2

**问题**​: 考虑函数 $f(x) = \begin{cases}\dfrac{\sin x}{x}, x \neq 0, \\ 1, x = 0.\end{cases}$，其中角度以弧度为单位。本题旨在研究当 $x$ 很小时，使用标准浮点运算计算 $f(x)$ 所产生的有效数字损失问题，并设计一种数值稳定的替代方法，以精确捕捉微小的减量 $d(x) = 1 - f(x)$。

从以下基本依据出发：
- 关于 $x = 0$ 的正弦函数的泰勒级数： $\sin x = x - \dfrac{x^{3}}{3!} + \dfrac{x^{5}}{5!} - \cdots$ 
- 由 $f(x)$ 导出的级数及其相关的减量 $d(x)$：$f(x) = 1 - \dfrac{x^{2}}{3!} + \dfrac{x^{4}}{5!} - \cdots,\ d(x) = 1 - f(x) = \dfrac{x^{2}}{3!} - \dfrac{x^{4}}{5!} + \dfrac{x^{6}}{7!} - \cdots$  
- 标准浮点模型：对于基本运算 $\circ \in \{+,-,\times,\div\}$，$\operatorname{fl}(a \circ b) = (a \circ b)(1 + \delta)$，其中 $|\delta| \le u$，$u$ 是工作精度的单位舍入误差。

---

**任务 1**：论证为何当 $x$ 很小时，直接计算 $\operatorname{fl}(\sin x)/\operatorname{fl}(x)$ 对于 $f(x)$ 具有较小的相对误差，但在形成 $1 - \operatorname{fl}(\sin x)/\operatorname{fl}(x)$ 时，会由于相减抵消而完全丢失关于减量 $d(x)$ 的信息。推导出一个用 $u$ 表示的阈值尺度，在该尺度下，朴素计算法无法可靠地解析 $d(x)$（以 $u$ 的渐近形式表示该阈值）。

对于第一问，假设 $x$ 是精确数字，并令其计算值为 $\hat f(x)$，则：

$$
\begin{aligned}
\hat f(x) =& \operatorname{fl}\left( \dfrac{\operatorname{fl}(\sin x)}{x} \right) = \dfrac{\operatorname{fl}(\sin x)}{x} (1+\delta_1) = \dfrac{\sin x}{x}(1+\delta_1)(1+\delta_2) \\
=& \dfrac{\sin x}{x} (1+\delta_1 + \delta_2 + \delta_1 \delta_2 ) \approx \dfrac{\sin x}{x} (1+\delta_1 + \delta_2) = f(x)(1+\delta_1 + \delta_2)
\end{aligned}
$$

其中 $|\delta_1|, |\delta_2| \le u$，故计算 $f(x)$ 的总相对误差为

$$
\left| \dfrac{\hat f(x) - f(x)}{f(x)} \right| \approx |\delta_1 + \delta_2| \le |\delta_1| + |\delta_2| \le 2u
$$

这个相对误差很小，量级与单位舍入误差 $u$ 相当，因此，直接计算 $f(x)$ 在其整个定义域内都是数值稳定的

对于第二问，假设 $x$ 是精确数字，并令其计算值为 $\hat d(x)$，则：

$$
\begin{aligned}
\hat d(x) =& \operatorname{fl}(1-\hat f(x)) = (1-\hat f(x))(1+\delta_3) \approx (1-f(x)(1+\delta_1 + \delta_2))(1+\delta_3) \\
=& (1-f(x) + f(x)(\delta_1 + \delta_2))(1+\delta_3) = (d(x) + f(x)(\delta_1 + \delta_2))(1+\delta_3) \\
=& d(x) + f(x)(\delta_1 + \delta_2) + d(x)\delta_3 + f(x)(\delta_1 + \delta_2)\delta_3 \\
\approx & d(x) + f(x)(\delta_1 + \delta_2) + d(x)\delta_3
\end{aligned}
$$

其中 $|\delta_3| \le u$，故计算 $d(x)$ 的总相对误差为

$$
\left| \dfrac{\hat d(x) - d(x)}{d(x)} \right| \approx \left| \dfrac{f(x)(\delta_1 + \delta_2) + d(x)\delta_3}{d(x)} \right| = \left| \dfrac{f(x)}{d(x)}(\delta_1 + \delta_2) + \delta_3 \right|
$$

对于小 $x$，有 $f(x) \approx 1,\ d(x) \approx x^2 / 6$，误差由第一项主导，故

$$
\left| \dfrac{\hat d(x) - d(x)}{d(x)} \right| \approx \left| \dfrac{f(x)}{d(x)} (\delta_1 + \delta_2) \right| \approx \dfrac{6}{x^2} | \delta_1 + \delta_2 | \lesssim \dfrac{12u}{x^2}
$$

当这个相对误差达到 $1$ 的量级或更大时，朴素计算变得不可靠。令 $12u / x^2 \approx 1$ 得到阈值 $|x| \approx \sqrt{12u}$ 

对于双精度运算，$u = 2^{-53} \approx 1.11 \times 10^{-16}$，阈值 $|x| \approx 3.65 \times 10^{-8}$。对于小于等于此尺度的 $|x|$ 值，$d(x)$ 的朴素计算会丢失其他部分或全部有效数字。该阈值的渐进量级为 $O(\sqrt u)$

```python
import numpy as np
from decimal import Decimal, getcontext

def solve():
    # 设置高精度参考计算的精度，50 位就足够了
    getcontext().prec = 50

    def reference_d(x_str: str) -> Decimal:
        """
        利用其泰勒级数，以高精度计算 d(x)。
        """
        if x_str == '0':
            return Decimal(0)

        x = Decimal(x_str)
        x_sq = x * x

        k = 1
        term = x_sq / Decimal(6)  # First term (k=1)
        d_val = term
        
        # Sum until the next term is smaller than the context precision
        while abs(term) > Decimal('1e-50'):
            k += 1
            term *= -x_sq / Decimal((2 * k) * (2 * k + 1))
            d_val += term
        
        return d_val

    def naive_f(x: float) -> float:
        """
        暴力计算 f(x) = sin(x)/x
        """
        if x == 0.0:
            return 1.0
        return np.sin(x) / x

    def stable_d(x: float, threshold: float) -> float:
        """
        使用一种稳定的混合算法计算 d(x)
        """
        if x == 0.0:
            return 0.0
        
        if abs(x) < threshold:
            x_sq = x * x
            term = x_sq / 6.0
            d_val = term
            
            for k_iter in range(2, 15):
                term *= -x_sq / ((2 * k_iter) * (2 * k_iter + 1))
                d_val_prev = d_val
                d_val += term
                if d_val == d_val_prev:
                    break
            return d_val
        else:
            f_val = np.sin(x) / x
            return 1.0 - f_val

    test_cases_str = ['0', '1e-12', '1e-10', '1e-8', '-1e-7', '1e-7', '1e-4', '1e-1']
    test_cases_float = [float(x) for x in test_cases_str]
    threshold = 1e-7

    all_results = []
    for x_str, x_float in zip(test_cases_str, test_cases_float):
        # 1. High-precision reference calculation
        d_ref_dec = reference_d(x_str)
        f_ref_dec = Decimal(1) - d_ref_dec
        d_ref = float(d_ref_dec)
        f_ref = float(f_ref_dec)

        # 2. Naive computation
        f_naive_val = naive_f(x_float)
        d_naive_val = 1.0 - f_naive_val

        # 3. Stable computation for the decrement
        d_stable_val = stable_d(x_float, threshold)

        # 4. Compute error metrics
        if x_float == 0.0:
            err_f_naive = 0.0
            err_d_naive = 0.0
            err_d_stable = 0.0
        else:
            # Relative error of naive f(x)
            err_f_naive = abs((f_naive_val - f_ref) / f_ref) if f_ref != 0 else 0.0
            
            if d_ref == 0.0:
                # This branch should not be taken for x != 0
                err_d_naive = 0.0 if d_naive_val == 0.0 else float('inf')
                err_d_stable = 0.0 if d_stable_val == 0.0 else float('inf')
            else:
                # Relative error of naive d(x)
                err_d_naive = abs((d_naive_val - d_ref) / d_ref)
                # Relative error of stable d(x)
                err_d_stable = abs((d_stable_val - d_ref) / d_ref)
        
        all_results.append([err_f_naive, err_d_naive, err_d_stable])

    # Format output as a string representing a list of lists, without spaces.
    formatted_results = [f"[{r[0]},{r[1]},{r[2]}]" for r in all_results]
    print(f"[{','.join(formatted_results)}]")

solve()
```

**问题**​：考虑非线性方程 $f(x) = x^3 - 3x + 1 = 0$。任务是分析计算出的根对于函数和初始猜测值的微小扰动的敏感性。

定义扰动函数族 $f_\varepsilon(x) = f(x) + \varepsilon\,g(x)$，其中 $\varepsilon$ 是一个小的实数参数，$g(x)$ 是一个光滑函数。比较两种求根方法的行为：
- 牛顿-拉弗森法（牛顿法），该方法需要一个可微函数和一个初始猜测值。

---

**任务 1**：讨论在单根处根映射 $f \mapsto x^\star$ 的适定性，并根据函数的加性扰动凭经验估计根的绝对条件数。

对于求根问题 $f(x) = 0$，“输入数据”是函数 $f$ 本身。我们关心的是当 $f$ 受到扰动时，根 $x^\star$ 如何变化。

由于 $x^\star$ 是一个单根，$f'(x^\star) \neq 0$。这确保了在 $\varepsilon=0$ 附近，$x(\varepsilon)$ 是 $\varepsilon$ 的一个可微函数。

对恒等式 $f(x(\varepsilon)) + \varepsilon g(x(\varepsilon)) = 0$ 关于 $\varepsilon$ 求导：$\frac{d}{d\varepsilon} \left[ f(x(\varepsilon)) + \varepsilon g(x(\varepsilon)) \right] = 0$ 

应用链式法则得到：$f'(x(\varepsilon)) \frac{dx}{d\varepsilon} + g(x(\varepsilon)) + \varepsilon g'(x(\varepsilon)) \frac{dx}{d\varepsilon} = 0$ 

在 $\varepsilon = 0$ 处求值，并注意到 $x(0) = x^\star$，方程简化为：$f'(x^\star) \frac{dx}{d\varepsilon}\bigg|_{\varepsilon=0} + g(x^\star) = 0$ 

解出这个代表根对扰动敏感性的导数，得到：$\frac{dx}{d\varepsilon}\bigg|_{\varepsilon=0} = - \frac{g(x^\star)}{f'(x^\star)}$ 

对于一个小的非零 $\varepsilon$，根的变化量 $\Delta x = x(\varepsilon) - x^\star$ 可以通过一阶泰勒展开来近似：$\Delta x \approx \varepsilon \frac{dx}{d\varepsilon}\bigg|_{\varepsilon=0} = -\varepsilon \frac{g(x^\star)}{f'(x^\star)}$ 

因此，这个预测位移的大小是：$\Delta x_{\text{pred}} = |\Delta x| \approx \left| \frac{\varepsilon g(x^\star)}{f'(x^\star)} \right|$ 

一般确切的根 $x^\star$ 是未知的。我们用其数值近似值 $x_0$ 来代替它，该近似值由未扰动方程（$\varepsilon=0$）计算得出。最终得到公式：$\Delta x_{\text{pred}} = \left| \dfrac{\varepsilon\,g(x_0)}{f'(x_0)} \right|$。项 $\left| \frac{g(x_0)}{f'(x_0)} \right|$ 是根相对于扰动 $g(x)$ 的估计绝对条件数。

**解答** 

**二分法**​：对于一个连续函数 $h(x)$，如果在区间 $[a, b]$ 上 $h(a)$ 和 $h(b)$ 异号，该方法保证收敛。它通过迭代地将区间减半，同时保持根被包围在区间内。在每一步，计算中点 $c = (a+b)/2$。如果 $h(a)h(c)<0$，新区间变为 $[a, c]$，否则变为 $[c, b]$。当区间宽度 $b-a$ 小于容差 $10^{-14}$ 时，终止。

**牛顿法**​：这种迭代方法可以找到实值函数 $h(x)$ 根的越来越好的近似值。迭代由以下公式定义：$x_{k+1} = x_k - \frac{h(x_k)}{h'(x_k)}$。如果初始猜测值 $x_0$ 足够接近一个单根，该方法会二次收敛。我们将把这个方法应用于扰动函数 $h(x) = f_\varepsilon(x) = x^3 - 3x + 1 + \varepsilon g(x)$，使用其导数 $h'(x) = f'_\varepsilon(x) = 3x^2 - 3 + \varepsilon g'(x)$。当绝对步长 $|x_{k+1} - x_k|$ 小于容差 $10^{-14}$ 时，终止。

对于每个测试案例，未扰动的函数是 $f(x) = x^3 - 3x + 1$，其导数为 $f'(x) = 3x^2 - 3$。该函数有三个不同的实根，分别位于区间 $[-2, -1],\ [0, 1],\ [1, 2]$ 中。

代码如下：

```python
import numpy as np

def solve():
    # 定义全局参数
    TOL = 1e-14
    MAX_ITER = 200

    def f(x):
        return x**3 - 3*x + 1

    def f_prime(x):
        return 3*x**2 - 3

    # 定义扰动函数及其导数
    def g_x(x): return x
    def g_x_prime(x): return 1.0
    def g_sin(x): return np.sin(x)
    def g_sin_prime(x): return np.cos(x)

    def bisection(func, a, b, tol=TOL, max_iter=MAX_ITER):
        """
        二分法
        返回根和迭代次数
        """
        fa = func(a)
        if fa * func(b) == 0:
            # 这种情况不应该发生。
            raise ValueError("Function has the same sign at interval endpoints.")
        
        iterations = 0
        while (b - a) > tol and iterations < max_iter:
            iterations += 1
            c = a + (b - a) / 2.0
            fc = func(c)
            if fc == 0.0:
                break
            if fa * fc < 0:
                b = c
            else:
                a = c
                fa = fc
        return a + (b - a) / 2.0, iterations

    def newton(func, func_prime, x0, tol=TOL, max_iter=MAX_ITER):
        """
        牛顿法
        返回根和迭代次数
        """
        xk = x0
        iterations = 0
        while iterations < max_iter:
            iterations += 1
            f_val = func(xk)
            fp_val = func_prime(xk)
            
            if fp_val == 0.0:
                break 
            
            step = f_val / fp_val
            xk_next = xk - step
            
            if abs(step) < tol:
                return xk_next, iterations
            
            xk = xk_next
        return xk, iterations

    results = []

    # Case 1
    eps1 = 1e-6
    g1, _ = g_x, g_x_prime
    f_eps1 = lambda x: f(x) + eps1 * g1(x)
    
    x0_c1, _ = bisection(f, 1.0, 2.0)
    xe_c1, _ = bisection(f_eps1, 1.0, 2.0)
    
    dx_obs1 = abs(xe_c1 - x0_c1)
    dx_pred1 = abs((eps1 * g1(x0_c1)) / f_prime(x0_c1))
    results.extend([dx_obs1, dx_pred1])
    
    # 为 Case 4 存储基准根
    baseline_bisection_root_from_c1 = x0_c1

    # Case 2
    eps2 = 1e-6
    g2, g2_prime = g_x, g_x_prime
    f_eps2 = lambda x: f(x) + eps2 * g2(x)
    fp_eps2 = lambda x: f_prime(x) + eps2 * g2_prime(x)

    dx_obs2 = abs(xe_c2 - x0_c2)
    dx_pred2 = abs((eps2 * g2(x0_c2)) / f_prime(x0_c2))
    results.extend([dx_obs2, dx_pred2])

    # 为 Case 3 存储基准根
    baseline_newton_root_from_c2 = x0_c2

    # Case 3
    x_c3, n_c3 = newton(f, f_prime, 0.2)
    dx_c3 = abs(x_c3 - baseline_newton_root_from_c2)
    results.extend([dx_c3, n_c3])

    # Case 4
    x_c4, n_c4 = bisection(f, 1.1, 2.0)
    dx_c4 = abs(x_c4 - baseline_bisection_root_from_c1)

    # Case 5
    eps5 = 1e-6
    g5, _ = g_x, g_x_prime
    f_eps5 = lambda x: f(x) + eps5 * g5(x)

    # Case 6

    g6, _ = g_x, g_x_prime
    f_eps6 = lambda x: f(x) + eps6 * g6(x)

    x0_c6, _ = bisection(f, -2.0, -1.0)
    xe_c6, _ = bisection(f_eps6, -2.0, -1.0)

    dx_obs6 = abs(xe_c6 - x0_c6)
    dx_pred6 = abs((eps6 * g6(x0_c6)) / f_prime(x0_c6))
    results.extend([dx_obs6, dx_pred6])

    # Case 7
    eps7 = 1e-12
    g7, g7_prime = g_sin, g_sin_prime
    f_eps7 = lambda x: f(x) + eps7 * g7(x)
    fp_eps7 = lambda x: f_prime(x) + eps7 * g7_prime(x)

    xe_c7, _ = newton(f_eps7, fp_eps7, 0.3)

    dx_pred7 = abs((eps7 * g7(x0_c7)) / f_prime(x0_c7))
    results.extend([dx_obs7, dx_pred7])

    # 将所有结果转换为字符串，用逗号分隔，并用方括号括起来。
    output_str = f"[{','.join(map(str, results))}]"
```
