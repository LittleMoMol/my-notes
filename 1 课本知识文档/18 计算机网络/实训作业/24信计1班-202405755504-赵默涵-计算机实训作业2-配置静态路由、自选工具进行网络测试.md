## 1-6 实训分析
### 1-6-1 静态路由的核心要点
1. **PC 的 IP 与网关关系**：PC1 的 IP 为 `192.168.1.100/24`，与 RA 的 GE0/0/1 接口 `192.168.1.1/24` 处于同一网段，PC1 的网关设为 `192.168.1.1`。请说明为什么网关必须是路由器直连接口的 IP？
    - **我的结论**：网关的本质是 PC 所在网段的"出口"，即负责将该网段数据转发到其他网络的设备接口。PC 在发送跨网段数据时，会将数据包交给网关处理。因此，网关 IP 必须与 PC 的 IP **处于同一网段**，这样 PC 才能通过 ARP 协议解析到网关的 MAC 地址，完成二层帧封装并交付给路由器。如果网关设为非直连接口的 IP，PC 发出的 ARP 请求将得不到响应，数据帧无法封装，跨网段通信彻底失败。在本实验中，PC1 的网关设为 RA 的 GE0/0/1 接口 `192.168.1.1`，与 PC1 自身 `192.168.1.100/24` 同属 `192.168.1.0/24` 网段，满足直连可达条件，PC1 才能将数据包成功交给 RA 进行路由转发。
2. **串口 IP 同网段**：RA 的 Serial4/0/0 为 `10.0.0.1/8`，RB 的 Serial4/0/0 为 `10.0.0.2/8`，两者处于同一网段。请说明为什么串口两端必须配置同一网段的 IP？
    - **我的结论**：路由器之间的串口用于直连互联，属于点到点链路。当 RA 需要将数据包转发给 RB 时，下一跳指向 `10.0.0.2`，RA 必须先确认该下一跳是否"可达"。如果两端 IP 不在同一网段，RA 会认为 `10.0.0.2` 不属于直连网络，无法通过本地接口直接送达，路由表中该静态路由条目将显示为"不可达"（Inactive），数据不会被转发。只有两端配置同网段 IP，路由器才能通过串口直接发送 ARP（或点对点协议自带的地址学习）获取对端地址，建立直连路由，静态路由的下一跳才能生效。本实验中 RA 的 `10.0.0.1/8` 与 RB 的 `10.0.0.2/8` 同属 `10.0.0.0/8` 网段，串口链路 UP 后直连路由自动生成，为跨网段静态路由提供了底层转发基础。
3. **静态路由的双向性**：RA 上配置了到 `192.168.2.0/24` 的静态路由，下一跳为 `10.0.0.2`；RB 上也配置了到 `192.168.1.0/24` 的静态路由，下一跳为 `10.0.0.1`。请解释为什么要"有去有回"？
    - **我的结论**：TCP/IP 网络通信是双向的。PC1 ping PC2 时，请求包（Echo Request）从 PC1 出发，经 RA 转发至 RB 再送达 PC2；但 PC2 收到后需要返回应答包（Echo Reply），该应答包的目的地址是 `192.168.1.100`，必须经由 RB 转发回 RA 再送回 PC1。如果仅在 RA 上配置去程路由而 RB 上没有回程路由，PC2 的应答包在 RB 处将被丢弃（RB 路由表中无 `192.168.1.0/24` 的匹配条目，只能走默认路由或丢弃），导致 ping 显示超时。因此，在两端路由器上分别配置指向对方网段的静态路由，形成"有去有回"的完整路径，是实现双向通信的必要条件。本实验通过在 RA 和 RB 上各配一条静态路由，成功实现了 PC1 与 PC2 的全互通。
4. **直连路由 vs 静态路由**：在路由表中，Direct 路由的优先级为 0，Static 路由的优先级为 60。请解释两者的区别。
    - **我的结论**：直连路由是路由器"家门口"的路，自动知晓；静态路由是"去别人家"的路，需要人工指路。优先级数值越小越优先，直连路由优先级 0 意味着只要接口正常，直连网段永远可达，不会被其他路由协议覆盖。
	    ![[Pasted image 20261101225423.png|875]]
5. **tracert 路径分析**：从 PC1 tracert PC2，路径为 192.168.1.1 → 10.0.0.2 → 192.168.2.100。请解释每一跳代表的含义。
    - **我的结论**：
	    tracert 通过发送 TTL 逐跳递增的 ICMP 报文来追踪路径，每一跳对应数据包经过的一个三层设备接口：
		- 第 1 跳 192.168.1.1：RA 连接 PC1 的以太网接口（GE0/0/1）。PC1 发出的数据包首先到达默认网关 RA，TTL 在此处减 1 并触发超时响应，标识为第 1 跳。
		- 第 2 跳 10.0.0.2：RB 连接 RA 的串口接口（Serial4/0/0）。RA 根据静态路由将数据包从串口转发出去，RB 接收后 TTL 再减 1，触发第 2 跳响应。此跳证明 RA-RB 广域网链路已通，静态路由下一跳生效。
		- 第 3 跳 192.168.2.100：目标主机 PC2 的 IP 地址。数据包经 RB 查路由表后从 GE0/0/1 接口送达 PC2，PC2 收到后直接返回 ICMP 端口不可达或 Echo Reply 报文，标识为最终目的地。
		
		三跳路径完整展示了数据从源网段（192.168.1.0/24）经广域网互联链路（10.0.0.0/8）到达目的网段（192.168.2.0/24）的全过程，验证了静态路由配置的正确性和网络的端到端连通性。

## 2-2 实验环境

- **网络环境**：校园网 / 实验室局域网 / 家庭宽带
- **主要工具**：
    - `ping`
    - `ipconfig`（Windows）或 `ifconfig` / `ip`（Linux）

    - `nslookup`
    - `netstat`
    - `Wireshark`（可选，抓包分析）
## 2-3 实验内容与步骤
### 2-3-1 查看本机网络配置
**命令**：
```bash
ipconfig /all
```

**实验现象**：
- 显示本机 IP 地址、子网掩码、默认网关、DNS 服务器等信息；
- 可确认当前主机是否正确获取网络参数。

![[Pasted image 20261101230651.png|725]]

**结果分析**：
- IP 地址为 `192.168.x.x`，说明处于私有局域网中；
- 默认网关为 `192.168.1.1`，用于访问外部网络；
- DNS 服务器配置正确，域名解析可正常进行。
### 2-3-2 测试网络连通性（ping）
**命令**：
```bash
ping www.baidu.com
```

**实验现象**：
- 返回 4 个 ICMP 数据包；
- 显示每个数据包的字节数、TTL、响应时间；
- 无丢包，连通性正常。

![[Pasted image 20261101230739.png|775]]

结果分析：
- `ping` 利用 ICMP 协议检测主机是否可达；
- 响应时间一般在几十毫秒以内，说明网络状况良好；
- TTL 值可大致判断目标主机操作系统及经过的路由跳数。
### 2-3-3 路由路径追踪（tracert）
**命令**：
```bash
tracert www.baidu.com
```

**实验现象**：
- 显示从本机到目标主机所经过的每一跳路由器；
- 每一跳显示 IP 地址及响应时间。

![[Pasted image 20261101230948.png|750]]

**结果分析**：
- 可观察数据包在网络中的转发路径；
- 若出现某一跳响应时间过长或超时，可能说明该节点存在网络拥塞或限制 ICMP 包；
- 有助于定位网络故障位置。
### 2-3-4 域名解析测试（nslookup）
**命令**：
```bash
nslookup www.baidu.com
```

**实验现象**：
- 显示域名对应的 IP 地址；
- 显示提供解析服务的 DNS 服务器地址。

![[Pasted image 20261101231010.png|500]]

**结果分析**：
- 域名解析是访问网络服务的前提；
- 若解析失败，即使网络连通也无法正常访问网站；
- 可判断 DNS 服务器工作是否正常。

**实验现象**：
- 显示当前所有 TCP、UDP 连接及监听端口；

![[Pasted image 20261101231103.png|675]]

**结果分析**：
- 可查看本机开放的服务端口；

- 对网络安全和故障排查有重要意义。

## 2-5 问题与思考
1. 为什么有时 ping 不通，但网页仍能访问？**​
    - 部分服务器禁用 ICMP 协议，导致 ping 失败，但 HTTP/HTTPS 仍可正常访问。
2. tracert 出现“请求超时”是否一定表示网络故障？**​
    - 不一定，部分路由器出于安全或性能考虑，不响应 ICMP 数据包。
3. 如何判断是 DNS 问题还是网络连通性问题？**​
    - 可直接 ping IP 地址：若 IP 可达但域名不可达，通常为 DNS 问题。
